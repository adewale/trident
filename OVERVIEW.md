# Benchmark overview

Trident's public workloads are community output admission and API/CLI costs, plus the portable authored family/scaling campaign. Use [the benchmark guide](BENCHMARKS.md) to decide whether a workload answers your question.

The remaining inherited workloads—Dave, authored fidelity, upstream assertions, startup, release/peer, editor and source diagnostics—remain callable through [the source adapter](adapters/agentic/README.md). Their fixed-engine or source dependencies are explicit. They are not all independent benchmarks and do not make every catalog project benchmark-ready.

[Methodology](METHODOLOGY.md) defines the common rules. [Measurement rules](MEASUREMENT.md) explain their limits. [Results](results/README.md) describes collecting fresh evidence; no old score is presented as current.


## Coverage and correctness

The frozen corpus records input intent separately from observed acceptance: render workloads, parser-only fixtures and invalid/diagnostic cases have different denominators. Positive-render comparisons require declared render intent and actual pinned-Mermaid admission. Missing evidence stays unavailable; it cannot shrink the declared workload or become a fast successful render.

Required-family reports retain Event Modeling and ZenUML alongside the other required families while upstream maturity questions remain explicit. Supporting one representative does not establish every feature, option or cross-feature combination. Native models, authored identities/relations, owned SVG paint and decoded raster content have separate checks. Labels alone do not establish full Mermaid fidelity. The [fidelity guide](fidelity/README.md) states the current projections and gaps.

SVG admission checks format and drawn-label candidates. PNG admission validates the full encoding, decodes bounded pixels and rejects blank content. Neither proves perceptual quality. Original upstream assertions retain their callbacks and expectations; unavailable private APIs and uncollected files remain coverage gaps. Source-literal replay is a different unit and cannot earn original-assertion credit.

## Invocation, performance and resources

The public community API/CLI lanes and portable kit use explicit catalog bindings and actual artifacts. The optional source adapter covers its declared library, browser, worker, editor, CLI and MCP operations; it does not make those interfaces available for every community tool. New exports such as `renderResolvedScene` require actual SVG and structured-sidecar consumption and qualification before a successful invocation can be claimed.

Separate fresh module import, initialization, first consumed result, changing-source work and repeated-source/cache-hit work. Common, large, architecture, interacting-feature and invalid-input cohorts answer different questions. A selected layout backend earns credit only when the adapter verifies that selection. Unsupported work is not a zero-cost result.

Use pinned Mermaid as the baseline only on a matched, qualified operation and cohort. Tool cost divided by observed Mermaid cost places Mermaid at 1; lower cost is better on that cost dimension. Coverage and checked meaning retain absolute denominators and the reference's own failures. Unmatched or missing baseline observations stay unranked. There is no overall weighted winner.

Portable calibration uses repeated same-artifact controls, separate fresh workers and independent rounds. Thousands of calls within five rounds do not supply six independent rounds for a finite two-sided 95% median-ratio interval. An incomplete or noisy run can produce a report without qualifying a performance claim.

Document V8 heap, instantaneous Linux Chromium-process RSS/PSS, whole-child peak RSS/CPU, retained output and delivered bytes retain their own scopes. Missing process mappings invalidate a browser-process total. These observations do not measure GPU device memory or establish per-render allocation and leak slopes. Dollar costs need observed usage and explicit rates.

## Records and extraction

Benchmark execution remains outside CI; benchmark controller tests and product correctness checks are different work. Matching project records are reused with their original dates. A changed artifact, dependency manifest, corpus, qualifier or protocol invalidates the owning records; other matching projects need not rerun.

The compiled portable kit and record/report readers work without an Agentic checkout. Source-specific diagnostics remain behind the explicit adapter boundary described in [the package guide](README.md). Historical snapshots and large raw evidence stay outside the source tree; [the current completion work](docs/benchmark-completion.md) records the implementation scope, not a substitute for fresh measured results.
